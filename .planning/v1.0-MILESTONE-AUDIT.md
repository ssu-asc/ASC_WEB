## Cross-phase integration

- Auth profile role/activity controls privileged Edge access rather than client metadata.
- Semester roster drives project expectations, team membership, dashboards, and round-first staff overview.
- Fixed teams feed shared team submissions without allowing member-side team creation.
- Assignment windows feed dashboard, schedule, submission opening rules, deadlines, and late-state derivation.
- Markdown submission feeds exact staff review, trusted server-side ProjectDB frontmatter/path generation, durable approval state, and retryable publication state.
- Resource links and staff memo remain separate from Vault-backed shared credentials.
- Browser configuration contains only browser-safe Supabase values; privileged credentials remain server-side.
- Static Cloudflare Pages deployment and Supabase hosted runtime are connected at the root custom domain `https://ssu-asc.com`; hosted Edge CORS explicitly allows that production origin.

## Accepted operational follow-up

The first real staff approval will be used as the live ProjectDB write smoke to observe `report-01.md` creation and the persisted immutable commit SHA. This is not a code/release blocker because the publisher contract, deterministic report builder, durability/retry behavior, ProjectDB compatibility, hosted secret provisioning, and surrounding runtime boundaries are already verified. A failed write remains independently retryable without rolling back approval.

Notion synchronization is not part of the ASC_WEB v1.0 completion gate. Existing external resource sharing/ownership remains an operator responsibility.
